# Private Docker registry for Railway

The CNCF `registry` (distribution 3.1) behind HTTP basic authentication, with images on a volume.

```bash
docker login <your-domain> -u <AUTH_USERNAME>
docker tag myapp <your-domain>/myapp:1.0
docker push <your-domain>/myapp:1.0
```

## Why this exists

The common registry template on Railway runs `registry:2` with no authentication on a public
domain: anyone who finds the address can push and pull anything. Here the start script refuses to
run unless both `AUTH_USERNAME` and `AUTH_PASSWORD` are set, and writes the bcrypt
`htpasswd` file the registry requires from them on every start, so changing the password is a
variable change and a redeploy.

## Variables

| Variable | Purpose |
|---|---|
| `AUTH_USERNAME` | login for `docker login` |
| `AUTH_PASSWORD` | password, generated by the template |
| `PORT` | listen port, 5000 |
